# 开发与自检

给改这个插件的人看：怎么挂到本机跑、改完什么时候生效、自检怎么跑。

这份文档**不随包发布**——`package.json` 的 `files` 白名单里只有使用者需要的东西
（`lib`、`client.js`、`cordis.patch.yml`、`config.example.yml`、`README.md`）。

## 1. 挂到本机

以 `link:` 方式装进 profile，改完源码重启就生效：

```powershell
dsh plugin --profile web add <插件目录>
```

- 本包自带的 `cordis.patch.yml`（由 `package.json` 的 `dsh.bundle.patch` 指定）
  会把 `task-tree` 这一行插进 profile，装上即启用。
- **改了 `lib/*.js` 必须重启 `dsh web` 才生效。** 运行中的会话不追溯；排查任何行为
  问题之前，先确认进程加载的是刚改过的那份代码。
- `client.js` 走客户端插件那条路，只有在同一个 checkout 里同时跑着 `pnpm run dev:web`
  时才会自动重建，否则要刷新页面。

## 2. 自检

六个脚本都不 import 任何 `@deepseek-ai/*` 运行时包——插件以 `link:` 方式安装时，
从插件目录往上找不到宿主作用域的包，一旦 import 就根本跑不起来。
`verify-client.mjs` 因此自带一套最小的 `window` / `document` / React 替身，
真去物化 `client.js`、真调一次 `apply`、真渲染一遍条目。

```powershell
node verify-entry.mjs     # 入口装配：默认（安装即启用）/ 显式关闭两条路径各注册了什么
node verify-tools.mjs     # 工具层：schema、result 必填、三级约束
node verify-region.mjs    # 折叠行为：起点与终点怎么取、含真人消息整段不折、区间为空不注入
node verify-plan.mjs      # 计划树纯逻辑：状态流转、检查点、丢弃级联、渲染
node verify-pause.mjs     # 暂停闸门：挂起、放行、取消信号、真人发言、会话隔离
node verify-client.mjs    # 客户端条目：挂载点、样式注入、文案键集、各种渲染态
```

`verify-region.mjs` 用假 session 忠实复刻了 DSH surface 的三条硬规则
（替换保持位置、`sourceEventSeqs` 必须覆盖全部遮蔽节点、节点 0 重写约束），
否则测出来的东西不算数。

## 3. 改折叠规则时注意

- 折叠规则写在 `lib/region.js` 的 `foldRange()` 里，是**纯表层判断**：起点是
  **上一次 `tree_task_done` 之后的第一个 `create`**（更早没有 `done` 时取表层第一个
  `create`；区间里一次 `create` 都没有时回退到上一次 `done` 之后），终点是本次
  `tree_task_done`。**边界只有 `create` 与 `done` 两个**：`tree_task_plan` 不是边界，
  它的调用与返回跟普通过程一样会随区间收走。判定表见 `docs/06-折叠范围规则.md`。
  三层游标（`lib/store.js` 的 `surfaces/`）不参与折叠，只给界面看进度。
- 替换区间**必须跳过**紧邻的 `tool/result` 与上一次落下的通告，否则会把收过的结果
  再收一遍、一轮轮空折。
- 折叠落地后要重新数一遍：`reason=series` 的请求次数应当与折叠次数一一对应
  （见 `docs/03-折叠上下文实测.md`）。
