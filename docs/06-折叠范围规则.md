# 折叠范围规则（起点取「上次 done 之后的第一个 create/plan」）

这份文档定死一次折叠到底收走哪一段，是 `lib/region.js` 的 `foldRange()` 与
`verify-region.mjs` 的共同依据。

## 1. 一句话规则

**一次 `tree_task_done` 触发一次折叠；收走的是「本次 done 之前的、上一次 done 之后的
第一个 `tree_task_create` / `tree_task_plan`」到「本次 done 之前」之间的那一段过程。**

## 2. 记法

| 记号 | 含义 |
|---|---|
| `C` | 一次 `tree_task_create` 调用**连同它的 `tool/result`**（下同） |
| `P` | 一次 `tree_task_plan` 调用连同它的返回 |
| `D` | 一次 `tree_task_done` 调用连同它的返回 |
| `w` | 过程：读文件、跑命令、assistant 消息、`tool/result` 等 |
| `H` | 真人消息（`source.kind === "user"`） |

## 3. 五条判定（按顺序执行）

1. **终点**：表层里**最近的一次边界调用必须是 `D`**。不是 `D`（说明还没走到"完成"
   这一步）或表层里根本没有边界调用，本轮不折。
2. **基准 floor**：上一次 `D` 的位置之后（`prevDone + 1`）。
   **更早没有 `D` 时，floor 是表层开头**（节点 0 是系统提示词，受 DSH 重写保护，
   永远不进替换区间）。
3. **起点**：从 floor 到本次 `D` 之间，取**最早**的那次 `C` / `P`。
   区间里一次 `C` / `P` 都没有时，起点回退到 floor 自己（即上一次 `D` 的调用位置；
   更早没有 `D` 时回退到"表层第一个节点之后"）。
4. **区间**：起点那次调用的 `tool/result` **之后** → 本次 `D` 的调用**之前**。
   起点那次调用本身、以及本次 `D` 的调用与返回，都留在表层上。
   向后走时继续跳过紧邻的两样东西：起点调用自己的 `tool/result`，以及
   **上一次折叠落下的通告**（它已经是收过的结果，再收一次就会一轮轮空折下去）。
5. **两条硬约束**（与旧规则相同）：
   - 区间里**夹着真人消息**（`H`）→ 整段不折，一个节点都不动；
   - 区间**为空**（`from > to`）→ 什么都不注入，不追加、不留空消息。

## 4. 与旧规则的差异

| | 起点取谁 |
|---|---|
| 旧 | 表层里**上一个边界调用**——`create` / `plan` / `done` 都算 |
| 新 | 上一次 `done` 之后的**第一个** `create` / `plan`；更早没有 `done` 时取表层第一个 `create` / `plan` |

差别只有一处，但后果是实质的：**中间的 `create` / `plan` 不再是折叠的切点。**

- 旧规则下，`C → w → P → w → D` 只把 `P` 之后的 `w` 收走，`C` 与 `P` 之间那段 `w`
  永远留在上下文里（它后面紧跟的是 `P` 而不是 `D`，没有哪一次折叠会回头收它）。
- 新规则下，`C` 之后到 `D` 之前的全部内容——那段 `w`、`P` 的调用与返回、`P` 之后的 `w`
  ——收成一条通告。

**代价**：被跨过的那几次 `P`（`tree_task_plan` 的返回里带着当时的整棵树）会随过程一起
离开上下文。模型要重新看计划，调 `tree_task_status` 现取即可——与"计划状态不注入提示词"
是同一个立场。

## 5. 判定表

**按阶段推进读这张表**：真实会话里每次 `agent/pre-step` 只折一次，触发那一刻表层上
只到那一次 `done` 为止。所以同一个序列会分几次折，表中用"触发"列区分。

| # | 表层序列（早 → 晚） | 触发 | 起点 | 收走的区间 | 留在表层 |
|---|---|---|---|---|---|
| 1 | `C w P w D` | `D` | `C` | `w P w` | `C D` |
| 2 | `C w D` | `D` | `C` | `w` | `C D` |
| 3 | `C D`（紧邻，中间没有别的调用） | `D` | `C` | 空 → 不注入 | 全部 |
| 4 | `C P D`（只隔一次 `plan`） | `D` | `C` | `P` 的调用与返回 | `C D` |
| 5 | `C P D1 D2` | `D1` | `C` | `P` 的调用与返回 | `C D1` |
| 　 | 　 | `D2` | 回退 `D1` | 空 → 不注入 | `C D1 D2` |
| 6 | `C w D1 w D2` | `D1` | `C` | `w` | `C D1` |
| 　 | 　 | `D2` | 回退 `D1` | `w` | `C D1 D2` |
| 7 | `C w D1 w P w D2` | `D1` | `C` | `w` | `C D1` |
| 　 | 　 | `D2` | `P` | `w` | `C D1 w P D2` |
| 8 | `D1 w C w D2` | `D2` | `C` | `w` | `D1 w C D2` |
| 9 | `C w H w D` | `D` | `C` | `w H w` 含真人消息 → 整段不折 | 全部 |
| 10 | 表层里找不到 `C` / `P`（被压缩遮掉） | `D` | 表层第一个节点之后 | 多半撞上真人消息 → 不折 | 全部 |

### 已知取舍（第 7、8 行）

规则只看"上次 `done` 之后的**第一个** `create/plan`"，所以：

- **`D1` 与那个 `create/plan` 之间的过程不收**（第 7 行的 `w`、第 8 行的 `w`）。
  它既不在"上次 `done` 之后"的起点上，也不在起点之后，两次折叠都轮不到它。
- 想要连它们一起收，就得把起点下探到 `D1` 之后——那是另一条规则（`done → done` 全收），
  不在本次范围内。
- 同理，第 3 行的 `C D` 紧邻时区间本来就是空的，不注入任何通告。

## 6. 实现要点

`foldRange(session)` 的结构（`lib/region.js`）：

```
1. 从末尾往前找最近一次边界调用 → endIdx；不是 done 或找不到 → return null
2. 从 endIdx-1 往前找最近一次 done → prevDoneIdx（可能为 -1）
3. floor = prevDoneIdx === -1 ? 0 : prevDoneIdx + 1
4. 从 floor 往 endIdx 扫，取最早的一次 create/plan → startIdx；没有则 startIdx = prevDoneIdx
5. from = startIdx === -1 ? 1 : startIdx + 1
   while (from < endIdx) 跳过 tool/result 与插件通告
   to = endIdx - 1
   from > to → return null
6. 返回 { from, to, shadowed: nodes.slice(from, to + 1) }
```

`foldOnce()` 里原有两条判断不动：区间含真人消息整段不折；`session.append` 抛错时
记 warn、保留原区间。

## 7. 自检覆盖

`verify-region.mjs` 里与这条规则直接相关的场景：

| 场景 | 钉住的东西 | 判定表 |
|---|---|---|
| 1 | 起点前移到 `C`，收 12 条；被跨过的 `P` 连同返回一起收走；`C`、`D` 的调用与返回保留 | 1 |
| 2 | 末尾最近一次边界调用不是 `done` 时不折 | — |
| 3 | `C P D`：起点是 `C`，只收 `P` 的调用与返回 | 4 |
| 3b | `C D` 紧邻：区间为空，不注入 | 3 |
| 4 / 5 | 区间之内夹真人消息整段不折；在区间之外不受影响 | 9 |
| 6 | 正文附上读写过的文件 | — |
| 7 | `C w D1 w D2` 折的是 `D1` 之后那 4 条 | 6 |
| 8 | 找不到 `C` / `P` 时退回表层第一个节点之后，撞上真人消息就不折 | 10 |
| 9 / 10 | 一轮只折一次；落下的通告不被重复收走 | — |
| 11 | 分阶段推进：`D1` 与下一个 `P` 之间的过程按规则不收，仍在表层 | 7、8 |
| 12 | 两次 `done` 紧邻：区间为空 | 5 |

假 session 自带 `sourceEventSeqs` 全覆盖校验（少一个就抛），所以"被跨过的调用确实进了
替换清单"由每次 `foldOnce` 隐式钉住，场景 1 另有显式断言。

三级游标同步不受影响——游标不参与折叠区间计算（见 `docs/02` §4.1）。
