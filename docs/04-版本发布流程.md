# 版本发布流程（含 registry 上架延迟）

**一句话规矩：`npm publish` 只发一次，然后去 registry 轮询等它上线；等不到就等着，
绝不在"查不到"的时候改版本号重发。**

违反这一条的后果，历史上已经出现三次：`0.3.1`、`0.3.3`、`0.3.5`/`0.3.6`——
同一个内容占掉两个版本号，registry 上的版本序列凭空多出一截。
根子不是发布失败，而是**上架有延迟，查询却立刻返回"没有"**。

## 1. 发布

```powershell
cd C:\apps\dsh_workspace\dsh-task-tree
# 先把 package.json 的 version 递增
npm publish
```

`publishConfig` 已把发布目标钉死在 `https://registry.npmjs.org`（公开），
本机 `npm config get registry` 指向的是 npmmirror 镜像，只影响查询、不影响发布。

打包内容由 `package.json` 的 `files` 白名单决定（`lib`、`client.js`、
`cordis.patch.yml`、`config.example.yml`、`README.md`）。发之前可以先看一遍：

```powershell
npm publish --dry-run
```

## 2. 上架有延迟：只有 registry 说上线了才算成功

`npm publish` 顺利跑完时会打印：

```
npm notice Publishing to https://registry.npmjs.org with tag latest and public access
npm notice Your package is being processed and may take a few minutes to become available.
```

**"may take a few minutes" 是字面意思。** 在这几分钟里：

- registry 的版本列表里**还没有**这个版本，`dist-tags.latest` 也还是上一个；
- `npm view` 因为走镜像 + 本地缓存，往往比 registry 更滞后。

所以"publish 成功"和"已经能在 registry 上查到"是两件事，中间隔着几分钟。

## 3. 延迟期间重试会看到两条误导性报错

这两条都**不代表发布失败**，它们只说明"这个版本号已经在处理中"：

```
npm error 409 Conflict - Cannot publish over previously staged version "0.3.5".
```

```
npm error 403 Forbidden - You cannot publish over the previously published versions: 0.3.5.
```

（`npm stage list` 此时会回 "No staged packages found"，也说明不了什么——
暂存/处理状态不在那个列表里。）

**看到这两条，正确反应是回去继续轮询，不是换版本号。**

## 4. 正确做法

```powershell
$name = "dsh-tree-task-flow"
$want = "0.3.7"          # 本次发布的版本号

for ($i = 1; $i -le 20; $i++) {
  Start-Sleep -Seconds 30
  $r = Invoke-RestMethod "https://registry.npmjs.org/$name" -Headers @{ "cache-control" = "no-cache" }
  if ($r.versions.PSObject.Properties.Name -contains $want) {
    Write-Output "已上线：$want（第 $i 次查询，latest = $($r.'dist-tags'.latest)）"
    break
  }
  Write-Output "第 $i 次查询：$want 还没上线，latest = $($r.'dist-tags'.latest)"
}
```

- 直接查 registry API，**不要用 `npm view`**：它受镜像与本地缓存影响，判断不了上架。
- 轮询到 10 分钟（20 次 × 30 秒）仍未上线，再去看 `~\.npm-cache\_logs\` 里
  publish 那次的 debug 日志，确认是真失败还是仍在处理。
- 只有确认失败（认证失败、包名/权限问题、日志里明确报错）才动版本号。

## 5. 实测时间线（2026-09-29，0.3.5 那次）

| 时间（本地） | 动作 | 结果 |
|---|---|---|
| 05:14 | `npm publish`（0.3.5） | 打印 "being processed and may take a few minutes" |
| 05:15 | 查 registry | **查不到 0.3.5**，latest 仍是 0.3.4 |
| 05:16:11 | 误判失败，重发 | `409 Cannot publish over previously staged version "0.3.5"` |
| 05:17:12 | —— | **registry 记录 0.3.5 于此刻上线** |
| 05:17:15 | 又换 npm@12 重发 | `403 previously published versions: 0.3.5` |
| 05:19 | 顺延成 0.3.6 再发 | 0.3.6 也上线，latest 变成 0.3.6 |

结果是 0.3.5 与 0.3.6 **内容完全相同**，版本序列白多一格。整条链路上真正出错的
只有一步：**在"查不到"的时候没有继续等，而是改了版本号。**

输出下结论。
